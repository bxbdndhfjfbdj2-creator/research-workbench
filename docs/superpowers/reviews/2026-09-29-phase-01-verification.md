## 已实现范围

第一阶段已经形成可运行的模块化单体基础：固定六人内部身份、Better Auth 登录、团队/研究组合/项目/项目成员关系、多维科研状态、ResearchTask、追加式 ResearchEvent、事务 Outbox、幂等 IntegrationInbox、可靠 Outbox Worker，以及研究组合、项目和团队的最小 Web 外壳。

本阶段没有接入 DeepSeek Harness、真实 GitHub 工程事件、科学决策系统、研究网络或共享资产；这些仍按批准路线图留在后续阶段。

## 自动化验证

最终 CI 在锁文件严格模式下执行：

- `pnpm install --frozen-lockfile`
- 全部 Vitest 单元/集成测试
- TypeScript 类型检查
- 基础 lint 闸门
- Next.js 生产构建
- Playwright Chromium 端到端验收

最终阶段审查额外加入并验证了三个关键不变量：

- `research_events` 在数据库边界禁止 UPDATE / DELETE，而不仅是应用接口不提供修改方法。
- 单团队最多存在一名激活的人类总负责人，并由应用事务检查与数据库部分唯一索引双重约束。
- Outbox 派发失败不保存任意异常正文，避免凭据或令牌通过错误文本进入持久化记录。

## 端到端验收场景

自动化浏览器验收覆盖：

- 总负责人登录后可以看到五个研究项目。
- 普通研究成员只看到自己参与的研究项目。
- 项目页可以同时呈现“理论=探索中、数据=冻结、主分析=验证中”等独立多维状态。

## 进入人工验收前的结论

自动化质量闸门已经通过。人工验收仍需由团队确认真实使用感受和组织语义，包括六个预创建账户、项目角色分配、多维状态展示、Outbox/Inbox 可追踪性和 Worker 重启恢复等。人工验收通过之前，不合并到 `main`，也不进入第二阶段。
