# 组织制度语言 0.2 设计补充

## 一、补充原因

正式实施计划自检时发现，已通过的 0.2 主规格中的动作语言无法完整表达当前 0.1 已存在的两类语义：

1. “更换负责人”需要取消目标对象的全部旧负责人关系，再建立新的负责人关系；
2. “成员离职”需要设置离职状态，并清理该成员作为主体的“属于/参与”关系，以及作为客体的“负责人”关系。

当前 0.1 实现已经明确具备这些行为，因此 0.2 若要满足“初始制度源码取代现有 `organization-actions.js` 语义”的要求，必须能够在制度语言中表达它们，而不能退回 JavaScript 特例。

本补充只增加动作层的两个确定性能力，不改变世界运行时内核，不引入自由自然语言、递归推理或条件量词。

## 二、动作输入支持存在类型并集

主规格原本规定动作输入为：

```text
输入 名称 文本
输入 成员 成员
```

补充为：一个输入可以是 `文本`，或者一个或多个已声明的存在类型。

例如：

```text
输入 对象 部门 项目组
```

表示 `?对象` 可以绑定一个“部门”或“项目组”实例。

### 编译规则

- `文本` 不能与存在类型混用；
- 一个实体输入声明中的所有类型都必须已经定义；
- 重复类型属于编译错误；
- 后续条件或效果若引用该输入，则其静态语义必须对该输入声明的所有可能类型都成立。

例如：

```text
输入 对象 部门 项目组
则 设置状态 ?对象 的 生命周期状态 为 已结束
```

只有在“部门”和“项目组”都定义了 `生命周期状态` 且都允许 `已结束` 时才能编译通过。

### GUI 规则

通用表单生成器对多类型实体输入，把当前世界中这些类型的实例合并为一个选择器，并继续根据制度中的简单状态前置条件做可选预筛选。

前端仍不得根据具体动作名写专用字段逻辑。

## 三、增加“取消所有关系”效果模板

动作效果新增：

```text
取消所有关系 从 <主体绑定或 *> 经 <关系名> 到 <客体绑定或 *>
```

示例：

```text
取消所有关系 从 ?对象 经 负责人 到 *
取消所有关系 从 ?成员 经 属于 到 *
取消所有关系 从 ?成员 经 参与 到 *
取消所有关系 从 * 经 负责人 到 ?成员
```

### 语义

这不是新的世界运行时原子操作。

动作物化器在当前世界中查找所有匹配该模式的关系，并按稳定顺序展开成零条或多条既有原子操作：

```text
取消关系
```

展开完成后，仍然把整个动作作为一次原子事件事务交给现有事件执行器。

因此：

- 匹配零条关系时，该效果是合法的空操作；
- 匹配多条关系时，要么全部与该动作其他效果一起提交，要么全部回滚；
- 核心运行时不新增“批量删除关系”分支；
- 事件 `changes` 仍记录实际展开并成功取消的具体关系。

### 静态检查

- `<关系名>` 必须已经定义；
- `从` 与 `到` 至少一侧必须是已声明绑定，不能同时为 `*`；
- 已绑定一侧的可能实体类型必须与该关系定义的主体/客体端兼容；
- `*` 仅表示该效果模板在当前世界中匹配任意合法端点，不建立新的动作绑定。

## 四、这不是条件量词

主规格“0.2 不实现条件中的量词”保持不变。

`*` 只允许出现在 `取消所有关系` 的动作效果模板中，用于把当前已存在关系物化成明确的 `取消关系` 原子操作；它不能用于：

- `要求` 条件；
- 创建存在；
- 设置状态；
- 建立关系；
- 推导新的绑定；
- 任意递归或规则推理。

因此这一补充不把 0.2 扩展为通用逻辑语言。

## 五、初始制度必须用上述能力表达现有语义

### 更换负责人

```text
动作 更换负责人
输入 对象 部门 项目组
输入 新负责人 成员
要求 状态 ?新负责人 的 任职状态 为 在职
则 取消所有关系 从 ?对象 经 负责人 到 *
并 建立关系 ?对象 的 负责人 为 ?新负责人
结束
```

物化时先取得目标对象全部当前负责人关系并展开取消操作，再建立新负责人关系。

### 成员离职

```text
动作 成员离职
输入 成员 成员
要求 状态 ?成员 的 任职状态 为 在职
则 设置状态 ?成员 的 任职状态 为 离职
并 取消所有关系 从 ?成员 经 属于 到 *
并 取消所有关系 从 ?成员 经 参与 到 *
并 取消所有关系 从 * 经 负责人 到 ?成员
结束
```

这样离职后成员不再保留部门归属、项目参与，也不再是任何部门或项目的负责人，同时世界仍保留该成员实体和离职状态以供历史查询。

### 结束组织对象

多类型输入也允许把当前“结束部门或项目”的能力写为：

```text
动作 结束组织对象
输入 对象 部门 项目组
则 设置状态 ?对象 的 生命周期状态 为 已结束
结束
```

## 六、验收补充

除主规格已有的委员会热更新场景外，0.2 回归必须证明：

1. 一个部门或项目存在多个负责人关系时，“更换负责人”由制度动作一次性取消全部旧负责人，并只建立新负责人关系；
2. 一个成员同时属于部门、参加多个项目并担任多个对象负责人时，“成员离职”由制度动作一次性清理全部相关运行关系；
3. 上述两个动作生成的最终底层事件只包含现有四种世界原子操作；
4. 整个 `src/model/organization-actions.js` 不再作为网页主运行路径，且不存在为“更换负责人”或“成员离职”保留的隐藏 JavaScript 特例。

## 七、范围不变

除本补充明确增加的“多存在类型输入”和“取消所有关系效果模板”外，0.2 主规格中的明确不做项全部保持不变。
